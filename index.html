Your learning goals

What you will learn

Objectives

  • Fragment it and calculate every fragment header field.
  • Watch fragments travel, arrive out of order, or go missing.
  • Rebuild the datagram from fragment offsets and detect gaps.
  • See how the Don't Fragment (DF) flag changes what the router does.

Learning outcomes

  • Calculate the maximum fragment payload and the number of fragments.
  • Read Identification, flags and fragment offset in an IPv4 header.
  • Explain why out-of-order arrival is not packet loss.
  • Explain what happens when a fragment is lost.

Why fragment at all?

Different links have different Maximum Transmission Units. When a datagram is larger than the MTU of the next link, the router either splits it into smaller pieces that fit, or, if DF is set, drops it and tells the sender to use a smaller size. Only the destination reassembles the pieces.

Theory

Open each topic. Equations use H for the IPv4 header length and MTU for the link limit.

What is an IP datagram?

An IPv4 datagram is a header (20 to 60 bytes, usually 20) followed by a payload from the transport layer. Total length = header + payload, held in a 16-bit field (maximum 65,535 bytes).

What is MTU, and why does fragmentation occur?

The MTU is the largest IP packet (header included) a link can carry, 1500 bytes on Ethernet. If a datagram is bigger than the MTU of the outgoing link, it has to be split.

fragmentation needed when datagram size > MTU

How does IPv4 fragmentation work?

The router cuts the payload into pieces and gives each piece its own IP header. Every piece except the last must carry a multiple of 8 bytes, because the offset field counts in 8-byte units.

Pmax = floor((MTU − H) / 8) × 8
fragment payload = min(Pmax, remaining payload)
total length = fragment payload + H

Example: 4000-byte datagram, MTU 1500, H = 20. Payload = 3980, Pmax = 1480, so the fragments carry 1480, 1480 and 1020 bytes.

Identification, fragment offset, MF and DF
  • Identification: a 16-bit value copied into every fragment, so the destination knows which fragments belong together.
  • Fragment offset: where this payload starts in the original payload, in 8-byte units. Offset = start byte / 8.
  • MF (More Fragments): 1 on every fragment except the last, which has MF = 0.
  • DF (Don't Fragment): if 1 and the packet is too big, the router drops it and sends ICMP Type 3, Code 4 (Fragmentation Needed) with the next-hop MTU.
How does reassembly happen?

The destination groups fragments by source, destination, protocol and Identification, then places each payload at byte position offset × 8. The final fragment (MF = 0) reveals the total length.

total payload = last offset × 8 + last fragment payload

The datagram is complete when the total is known and no byte range is missing.

Lost fragments and out-of-order arrival

Out of order: fragments may take different paths and arrive in any order. Because each carries its own offset, the destination still rebuilds the datagram correctly. Late is not lost.

Lost fragment: IP gives no retransmission. The destination keeps the partial datagram until the reassembly timer expires (RFC 791 suggests 15 s), then discards it and may send ICMP Time Exceeded (Type 11, Code 1). A higher layer such as TCP must resend the whole datagram, which is why losing one fragment is costly.

Assumption about header options in this lab

Header lengths of 24 and 28 bytes mean IP options are present. In real IPv4 only options marked "copied" go into every fragment. This lab assumes all options are copied, so every fragment has the same header length.

          Experiment documentation

          Aim

          To simulate IPv4 fragmentation when the MTU is smaller than the datagram, and to reassemble the original datagram at the destination.

          Required theory

          MTU, IPv4 header fields (Identification, flags, fragment offset), Pmax = floor((MTU − H) / 8) × 8, ICMP Fragmentation Needed, reassembly and timeout. See the Theory section.

          Procedure
          1. Open Experiment setup and set the datagram size, MTU, header length and DF flag.
          2. Press Simulate and watch the fragments travel in Interactive simulation.
          3. Open the Packet header inspector and record the fields of each fragment.
          4. In the Reassembly laboratory, deliver fragments in different orders, then lose one.
          5. Repeat with DF = 1 and with at least two other MTU values. Read the Results page.
          Observations

          Record in your notebook: Pmax, number of fragments, each offset, MF and total length, and the reassembly status for each trial.

          Result and conclusion

          Your results appear on the Results and analysis page after each run. Fragmentation succeeds only when DF = 0; the destination rebuilds the datagram only when every byte range has arrived before the timer expires.

          Viva questions
          1. Why must non-final fragment payloads be multiples of 8 bytes?
          2. Who performs reassembly, the router or the destination, and why?
          3. What does the router return when DF = 1 and the packet is too large?
          4. Why is losing one fragment costly for the whole datagram?
          5. How does the destination know it has the last fragment?
          6. How does the checksum change when the router decrements TTL?
