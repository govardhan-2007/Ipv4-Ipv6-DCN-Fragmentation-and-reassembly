    Your learning goals

    What you will learn

    Objectives

    • Create an IPv6 packet and compare its size with the Path MTU.
    • See the router drop an oversized packet and send ICMPv6 Packet Too Big.
    • Calculate every fragment's data size, offset, M flag and length.
    • Rebuild the packet from fragment offsets, in order, out of order or with a loss.

    Learning outcomes

    • Explain why only the source may fragment an IPv6 packet.
    • Calculate the maximum fragment data and the number of fragments.
    • Read the Next Header chain: base header 44, then Fragment Header.
    • Explain the 60-second reassembly timer and ICMPv6 Time Exceeded.

    Why does IPv6 fragment only at the source?

    In IPv4 every router on the path may fragment a datagram. IPv6 removes that work from routers: they forward faster and never keep fragments. If a packet is too big, the router drops it and tells the source the usable MTU. The source then sends smaller pieces, and only the destination reassembles them.

    The default worked example is a 4000-byte packet over a 1500-byte Path MTU: fragment data of 1448, 1448 and 1064 bytes, offsets 0, 181 and 362, and M flags 1, 1, 0.
