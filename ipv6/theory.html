Theory

Open each topic. Equations use P for the packet size and MTU for the Path MTU. The lab uses a simplified teaching model, listed in the last topic.

What is an IPv6 packet?

An IPv6 packet is a fixed 40-byte base header followed by the payload. The payload can hold extension headers and upper-layer data such as TCP, UDP or ICMPv6. There is no Header Length field and no header checksum, because the base header never changes size and link layers already check for errors.

P = 40 + Payload Length
Payload Length counts every byte after the 40-byte base header

Who is allowed to fragment in IPv6?

Only the source. A router that cannot forward a packet because it exceeds the outgoing link MTU discards it and returns ICMPv6 Packet Too Big (Type 2, Code 0) with the MTU of the next link. The source then sends smaller packets, or fragments them itself.

There is no DF flag in IPv6: routers are never allowed to fragment, so it is not needed.

Router: P > MTU → drop + ICMPv6 Packet Too Big (MTU)
Source: builds fragments that fit the Path MTU
Destination: reassembles

The Fragment Extension Header

Every fragment carries an 8-byte Fragment Header between the base header and the data. The base header's Next Header field is set to 44, which means "a Fragment Header follows".

The Next Header chain

Headers are chained. The base header points to the Fragment Header with value 44, and the Fragment Header points to the transport protocol.

IPv6 base header (Next Header = 44) → Fragment Header (Next Header = 17) → UDP header + data

Common values: TCP = 6, UDP = 17, ICMPv6 = 58. The value 44 names the Fragment Header, not a transport protocol. A packet that is not fragmented has no Fragment Header, so its base header carries the transport value (for example 17) directly.

Fragment offset and the M flag
  • Fragment offset: the position of this fragment's data inside the original fragmentable part, counted in 8-byte units. Offset = start byte ÷ 8.
  • M (More fragments): 1 on every fragment except the last, which has M = 0 and so reveals where the data ends.
  • Every fragment except the last must carry a multiple of 8 bytes, because the offset counts in 8-byte units.

Offset(i) = ByteStart(i) / 8
ByteStart(i) = Offset(i) × 8

How to calculate the fragments

The 40-byte base header is not fragmented: it is copied into every fragment. Only the bytes after it, the fragmentable part, are split.

F = P − 40
Dmax = floor((MTU − 40 − 8) / 8) × 8
D(i) = min(Dmax, R(i)) where R(i) = bytes still to send
Payload Length(i) = 8 + D(i)
Total length L(i) = 40 + 8 + D(i)

  • P: original packet size (includes the 40-byte base header).
  • F: fragmentable bytes.
  • Dmax: most data a non-final fragment may carry.
  • D(i), L(i): data and total length of fragment i.

The floor brackets round down, which guarantees a multiple of 8.

Path MTU Discovery and Packet Too Big

Path MTU Discovery finds the smallest MTU along the path. When a router cannot forward a packet it sends ICMPv6 Packet Too Big and the source learns the limit. IPv6 requires every link to support at least 1280 bytes, so the Path MTU is never below 1280.

ICMPv6 Packet Too Big: Type = 2, Code = 0, MTU = next-link MTU

In practice: TCP usually reacts by lowering its segment size. A UDP-style source may instead fragment. The lab shows the fragmenting source, because that is the behaviour this experiment studies.

Do not confuse this with IPv4's "Fragmentation Needed" (ICMP Type 3, Code 4). It reports the same kind of limit, but it is a different message.

Reassembly at the destination

Only the destination host reassembles. It groups fragments by source address, destination address and Identification, then puts each data block at byte Offset × 8. Arrival order never decides placement. The fragment with M = 0 gives the total length.

Start(i) = Offset(i) × 8
End(i) = Start(i) + D(i) − 1
Complete when the last fragment (M = 0) has arrived and no byte range is missing

Late is not lost. Out-of-order fragments still rebuild the packet. Lost fragment: there is no retransmission at the IP layer. The destination keeps the partial packet for up to 60 seconds (RFC 8200). If it is still incomplete it is discarded. If the first fragment (offset 0) had arrived, the destination sends ICMPv6 Time Exceeded (Type 3, Code 1) to the source. A higher layer must resend the whole packet.

Overlapping fragments are not allowed in IPv6 (RFC 5722). The lab never creates overlaps; exact duplicates are simply ignored.

Assumptions of this lab
  • The packet size includes the 40-byte base header. No other extension headers are present, so the Fragment Header follows the base header directly.
  • Link A (source to router) has an MTU of 9000 bytes. Link B has the Path MTU you choose, from 1280 to 9000 bytes.
  • The packet size ranges from 40 to 9000 bytes. Jumbograms are not modelled.
  • The base header uses Traffic Class 0, Flow Label 0 and Hop Limit 64. The router lowers the Hop Limit to 63. Fragments are not given new addresses.
